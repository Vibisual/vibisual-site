지표의 정의와 근거

설치 완료 수와 활성 사용자 수는 현재 미측정입니다.
다운로드 요청 수를 설치자·사용자·광고 도달 인원으로 제시하지 않습니다. 봇, 자동 업데이트, CI 검증, 같은 사람의 재다운로드가 포함될 수 있습니다.

지표의미한계
GitHub 스타저장소의 공개 스타 개수설치 또는 실제 사용을 증명하지 않습니다.
설치 파일 다운로드 요청현재 공개된 모든 릴리스의 .exe, .dmg, .AppImage, .deb, .rpm 다운로드 카운터 합계중복·자동 요청을 식별할 수 없으며 설치 성공 여부도 알 수 없습니다.
설치 완료·활성 사용자미측정 (null)앱에서 설치 완료나 사용 이벤트를 수집하지 않습니다. 0명이라는 뜻이 아닙니다.
웹사이트 방문자Abacus의 기존 누적 방문자 카운터브라우저 저장 표시로 중복을 줄입니다. 고유한 사람 수나 광고 도달 인원을 보증하지 않습니다.

계산과 원본 확인

설치 파일 다운로드 요청은 GitHub가 제공한 누적값을 그대로 합산합니다. 업데이트 메타데이터(YML), blockmap, ZIP, 체크섬은 제외합니다. 공개 사전 릴리스는 포함하고 비공개 초안은 제외합니다. 추정 봇 수나 과거 CI 기준값을 임의로 빼지 않습니다. 파일 삭제·교체 또는 GitHub의 집계 조정으로 합계가 감소할 수도 있습니다.

  • stats.json: GitHub 스타·설치 파일 다운로드 값, 기록 시점(asOf), 원본 스냅샷 경로와 SHA-256.
  • 현재 기록: JSON에서 확인할 수 있습니다.
  • 시점별 원본 스냅샷: 버전, 자산 ID·이름, 다운로드 카운터. 값이 바뀌거나 UTC 날짜가 바뀌면 새 파일을 보존합니다.
  • 집계 코드 · 기록 변경 이력 · GitHub 원본 API

API 조회·검증에 실패하면 이전 기록과 그 시점을 유지합니다. 이 기록은 관측 당시 GitHub 응답을 재검산할 수 있게 하는 자료이며, GitHub의 사람 판별이나 독립 감사를 대신하지 않습니다. 과거에 보존하지 않은 파일별·요청자별 이력은 복원할 수 없습니다.

방문 카운터의 기록과 중복 방지

웹사이트 방문자는 기존 Abacus vibisual-pro/site-total 누계를 사용합니다. 정식 사이트의 브라우저에서 탭 간 잠금 안에 기존 vibisual-visited 표시를 확인하고, 증가 시도 전에 pending을 저장합니다. 성공 시 완료 표시로 바꾸며, 응답이 불명확하면 증가를 자동 재시도하지 않습니다. 저장이나 잠금이 불가능하거나 미리보기·브라우저 자동화 환경이면 조회만 합니다.

이 방식은 동시 탭·저장 실패·응답 유실로 인한 중복 증가를 줄입니다. 반대로 집계 누락이 생길 수 있으며, 저장소 삭제·다른 브라우저·외부 자동 요청을 고유한 사람과 구분하지는 못합니다. 카운터 자체는 공개 쓰기가 가능한 외부 서비스이므로 직접적인 외부 증가 요청을 막거나 실제 방문자를 보증할 수 없습니다.

방문 카운터 관측 JSON에는 별도의 asOf, 집계 응답 {value}의 해시, 원본 스냅샷 경로, 이전 관측의 해시와 증감이 있습니다. 자동 기록은 읽기 전용 /get만 호출하며 카운터를 늘리지 않습니다. 같은 값의 같은 UTC 날짜에는 기존 관측 시각을 유지하고, 조회 실패 시 이전 정상 기록을 보존합니다. 유효한 하락과 0은 보정하지 않습니다. 이 기록에는 IP·기기 식별자·개별 방문 내역이 없습니다.

다운로드가 늘거나 줄었을 때 확인하는 방법

다운로드 스냅샷의 comparison은 같은 자산 ID의 카운터 변화와 신규·삭제·확장자 분류 변경의 기여를 구분합니다. 새로 나타난 자산의 누계 전부를 관측 구간의 신규 다운로드로 간주하지 않습니다. previousObservation이 이전 스냅샷과 해시를 가리키므로 변화량을 재계산할 수 있습니다. 집계 정의가 다르거나 이전 기록이 없으면 증가는 미확정으로 둡니다.

저장소에서 node .github/scripts/verify-site-metrics.mjs를 실행하면 현재 원본 해시·합계·이전 기록 대비 계산을 검산합니다. 검산 통과는 공개된 숫자의 내부 일치에 관한 결과이며, 사람 수나 독립 감사의 인증이 아닙니다. 새 앱 사용 정보나 최초 실행 정보의 수집은 추가하지 않았습니다.

Metric methodology

Verified installations and active users are not measured. Installer downloads are requests, not people, completed installations, or advertising reach.

We sum GitHub's cumulative download counters for .exe, .dmg, .AppImage, .deb, .rpm assets in public releases, including prereleases. Drafts, metadata, blockmaps, ZIP archives and checksums are excluded. Automated requests, updates, CI and repeat downloads may remain. We do not subtract guessed bot counts or a fixed CI baseline. Asset removals, replacements or upstream corrections can decrease the total.

stats.json links to timestamped per-asset evidence and its SHA-256. A new observation is recorded when source data changes or on a new UTC day. Failed or incomplete requests retain the previous record and its timestamp. The history supports recalculation of observed public counters, not an independent audit of human usage. Unknown installation and active-user counts are null, never zero or an estimate derived from downloads.

The visitor figure uses the existing Abacus counter. On the production origin, a browser lock serializes marker checks and requests across tabs. The existing marker is saved as pending before an increment attempt; an uncertain result is never automatically retried. Unavailable storage or locks, previews and browser automation use read-only requests. This reduces accidental duplicate increments but can undercount. Cleared storage, other browsers and external automated requests remain indistinguishable from people. The upstream counter is publicly writable and cannot establish verified visits or unique people.

Visitor observations preserve the public aggregate separately, with a timestamp, normalized {value} response hash, immutable snapshot and prior-observation link. The scheduled collector only calls /get. It stores no IP, device ID or individual browsing history. Unchanged observations on the same UTC date reuse their original timestamp; failures retain the last valid record. Valid decreases and zero are not clamped.

Download evidence includes a comparison by asset ID and a previousObservation hash link. Counter changes on retained installers are separated from assets entering or leaving the installer set. Newly listed counters are not assumed to be new downloads during the observation interval. Different methodologies or missing predecessors do not produce a growth claim. Run node .github/scripts/verify-site-metrics.mjs to recalculate saved evidence. This verifies consistency of public counters, not human usage or an independent audit.
